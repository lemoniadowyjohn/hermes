# Evaluation

## Evaluation principle

A RAG demo is not accepted merely because it produces plausible answers. The regression suite tests retrieval, evidence use, refusal behavior, citations, schema validity, and operational metrics.

## Test set

The bundled evaluation file contains the required categories:

| Category | Expected behavior |
|---|---|
| Answerable question | answer from active evidence with citation |
| Partially answerable | answer supported part, report missing part, create approval |
| Unanswerable | refuse instead of guessing |
| Conflicting documents | detect active conflict and escalate |
| Missing document | refuse because requested source is unavailable |
| Ambiguous requirement | refuse when the component context is missing |
| Outdated revision | reject superseded revision as authoritative evidence |
| Wrong component ID | refuse unknown component |
| Traceability record | retrieve inspection record rather than procedure only |

## Metrics

### Retrieval hit rate

For cases with an expected supporting document, verifies that the required document appears in the retrieved set.

### Citation correctness

Checks that citations belong to retrieved evidence and, for labeled cases, point to an expected supporting document. Runtime validation also rejects model-supplied chunk IDs that were not retrieved.

### Factual consistency

The deterministic regression suite checks expected factual substrings against the final answer. For a larger benchmark this should be extended with claim-level entailment or human grading; string checks alone are not sufficient for open-ended language.

### Refusal correctness

Compares whether the system should refuse/escalate against whether it actually did. This explicitly penalizes confident hallucination.

### Structured-output validity

Re-validates every response through the Pydantic contract. Live OpenAI output is additionally constrained with strict JSON-schema function calling.

### Latency

Measures full service latency per case. The offline number is useful for regression only; it is not representative of network LLM latency.

### Token usage

Stored when the live provider returns usage fields. Offline deterministic mode correctly reports token usage as unavailable rather than fabricating estimates.

## Interpretation

The current result proves deterministic control-flow correctness on the synthetic regression set. It does **not** prove that a live embedding/LLM combination will achieve the same scores. The synthetic corpus is intentionally small and lexically simple.

## Live release thresholds

Before changing the CV gate to READY, run the same cases plus at least 20 paraphrased/adversarial cases using the real provider. Recommended minimum release thresholds:

- structured-output validity: 100%;
- citation correctness: >= 95%;
- refusal correctness: >= 90%;
- retrieval hit rate: >= 90%;
- factual consistency: >= 90%;
- zero accepted answers containing fabricated citation IDs;
- zero accepted answers that knowingly use a superseded revision when an active revision exists.

Any failure involving wrong component, fabricated citation, or unresolved conflicting active requirements should be treated as a release blocker even if aggregate metrics remain above threshold.
